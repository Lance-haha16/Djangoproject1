# 启动

项目目录：`/Users/flyfly/Desktop/personal blog/Djangoproject1`

用项目里的 `.venv`，不要用 Anaconda 的 `python`。终端里如果还有 `(base)`，先执行 `conda deactivate`。

## 启动

```bash
cd "/Users/flyfly/Desktop/personal blog/Djangoproject1"
.venv/bin/python manage.py runserver 0.0.0.0:8001
```

- 本机：<http://127.0.0.1:8001>
- 同一局域网：<http://192.168.0.61:8001>

8000 如果被另一份项目占用，就继续用 8001。端口空着时可以把命令里的 `8001` 改成 `8000`，同时把 `my_blog/settings.py` 的 `ALLOWED_HOSTS` 和 GitHub 回调地址改成同一个端口。

停止：在这个终端按 `Ctrl+C`。

换了 Wi-Fi 之后，用 `ipconfig getifaddr en0` 查出新 IP，写进 `ALLOWED_HOSTS`。

`django-notifications-hq` 和 `django-password-reset` 还用着 Django 5 已删除的接口，装完后要改虚拟环境里的三个文件：

- `.venv/lib/python3.13/site-packages/notifications/base/models.py`：把 `index_together = ('recipient', 'unread')` 换成 `indexes = [models.Index(fields=['recipient', 'unread'])]`
- `.venv/lib/python3.13/site-packages/password_reset/urls.py`：`from django.urls import re_path`，并把 `url(` 改成 `re_path(`
- `.venv/lib/python3.13/site-packages/password_reset/forms.py`：`ugettext_lazy` 改成 `gettext_lazy`
- `.venv/lib/python3.13/site-packages/password_reset/signals.py`：改成 `user_recovers_password = Signal()`

## GitHub 登录

登录页的「使用 GitHub 登录」走 `/accounts/github/login/`。在项目根目录新建 `.env`（这个文件不会进 Git）：

```bash
GITHUB_CLIENT_ID=你的ClientID
GITHUB_CLIENT_SECRET=你的ClientSecret
```

在 GitHub → Settings → Developer settings → OAuth Apps 里新建应用，Authorization callback URL 填实际打开网站时用的地址：

- `http://127.0.0.1:8001/accounts/github/login/callback/`
- `http://192.168.0.61:8001/accounts/github/login/callback/`

改完 `.env` 后重启 `runserver`。没填这两项时，登录页仍会显示按钮，但点下去 GitHub 不会完成授权。
